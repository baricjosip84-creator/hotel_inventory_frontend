NEW CAUSAL SOURCE FINDING (BE131):
- Frontend src/lib/api.ts adds Idempotency-Key to every ordinary write.
- Backend routes/index.js attaches operational idempotency before inventory-capabilities routes.
- A successful saveCustomFieldValues() returns an ARRAY of saved rows.
- Backend src/middleware/idempotency.js fresh-claim and reclaimed-claim branches stored
  that ARRAY directly in idempotency_keys.response_body (type JSONB, 001_initial.sql).
- node-postgres serializes JS arrays as PostgreSQL ARRAY literals, not JSON; a JSONB
  input conversion can therefore fail with SQLSTATE 22P02 during response persistence.
- transactionMiddleware commits the business transaction before idempotency's response
  interceptor persists the response. Thus an HTTP 400 from the response interceptor can
  occur AFTER the underlying Custom Fields save commits. No proof exists this happened
  in the user's actual database; check F5 retrieval rather than assuming either outcome.

  explicitly with JSON.stringify(body === undefined ? null : body) and bind $2::jsonb.

- Preserve existing request hashing, isolation, concurrency, replay, and no-key behavior.
