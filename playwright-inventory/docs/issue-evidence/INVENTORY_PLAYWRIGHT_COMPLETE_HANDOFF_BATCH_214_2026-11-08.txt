### The recurring problems already diagnosed and fixed — do not reintroduce them

1. **Route interception:** `**/products`, `**/stock`, `**/suppliers`, `**/alerts`, etc. can also match the browser's document navigation; handlers must act on *intended API reads only* and not return JSON as HTML. Keep an automated document/API regression check. This explains many early all-RED batches and later Stock/Alerts problems.
2. **Bulk authentication:** Logging in for every test caused login-rate/refresh-state failures at 100+ tests. A naive shared cookie/refresh snapshot also caused worker restarts and cross-worker contention. Use the **working B214 fixture as baseline**, with verified worker/session isolation and bounded login renewal/retry. Do not invent a fresh auth architecture without reproducing its safety properties. Ensure dashboard navigation after auth where original specs expect it.
3. **Write protection:** Broad catch-all handlers and over-strict safety flags led to artificial failures. Never disable production write blocking to turn red into green. The guard must distinguish blocked unsafe network writes from safely intercepted mock responses; matching GET fixtures must not hijack unrelated POSTs.
4. **Selectors:** Strict duplicate-text locators, badge ambiguity, wrapper-vs-child panel locators, date/currency formatting and confirmation dialogs have caused failures. Match current DOM and behavior before creating next approved batch. Do not broaden assertions so much that they fail to prove the intended behavior.
5. **Bulk recovery policy:** Failed runs were analyzed using GitHub log ZIPs, passed IDs were retained, failed IDs were rechecked in smaller single-worker groups only if needed, and unresolved product-behavior cases were held rather than faked green. Do not use a fixed three-failure cutoff to leave many tests unexecuted inadvertently.
6. **Preflight responsibility:** Check each candidate's live-auth permissions, test fixtures, API route interception, synthetic GET-only safety, page nav, selectors, mock status and manifest/sha fingerprints before asking user for GitHub execution. Prior promises of 'preflight' sometimes missed runtime failures; local static checks are useful but **not a guarantee** of live GREEN.
